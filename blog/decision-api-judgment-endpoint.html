Модели вердиктов: judgment выделяется из chat completion

LLM · API · 25 ноября 2026 · 1 мин

На этой неделе Google выпустил Gemini Decisions API и присоединился к Jev и OpenAI. Форма у всех почти одна: yes/no (у Jev это Noul), выбор из вариантов, оценка по рубрике.

Большая часть production-вызовов LLM не генерация: модерация, триаж, матчинг схем, оценка в evals. Это judgment, и гнать его через чатовую модель — парсить свободный текст и надеяться, что формат не поедет.

Cloudflare и TypeSafe AI уже показывают production-кейсы.

Что делать с пайплайном:

  • если ответ — один из N вариантов или число, это decision, а не чат;
  • такие вызовы уходят на decision-endpoint, генерация остаётся для текста;
  • логируйте калибровку: 0.52 и 0.99 это разные yes.

Честно: chat completion API расползается на generation и judgment. Пайплайны упрощаются, когда judgment перестаёт быть задачей prompt engineering.
